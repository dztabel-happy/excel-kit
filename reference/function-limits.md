# 函数的限制与 Excel 的已知差异

函数层面哪些写法会报告不可得、哪些结果与 Excel 仍可能不同。一个函数是否受支持查 `help fn.<函数名>`；整类不支持的情形见 [unsupported.md](unsupported.md)。

## 会报告不可得的写法

下列写法仍报告不可得或诊断：以函数名作参数、经 `CHOOSE` 等选出再调用的 `LAMBDA`、名称含 `?` 的 `LET`／`LAMBDA` 变量；两边都只有坐标的空格交集（如 `=A1:C3 B2:D4`；有名称参与的交集照常计算）；不受支持的旧式数组公式（如单独的 `FREQUENCY(...)`）。不能把这一限制扩大成所有普通录入的数组计算都不可用。

- **显式交集与区域计数**：`@`／`SINGLE` 和 `AREAS` 已公开；显式交集成功时保留单格引用身份，数组取首格。实际调用这些内建入口时，自己的引用操作数若需要相对名称绑定、空格引用交集或 `INDEX` 多区域引用形式，仍不可得；未测的多冒号引用也会报告 `NONSCALAR_UNMEASURED_RANGE`。普通绝对名称、局部名称及普通联合不因此一律被拒绝。名称在自身作用域确定这两个内建入口的身份，与同名局部函数区分；已有其他函数跨名称作用域的 Excel 兼容性未验证。
- **交集公式的数组模式**：Excel 有时会把 `@SEQUENCE(...)` 或 `@溢出引用` 去掉显式包裹，保存为旧式公式；本程序读入后可能报 `ARRAY_MODE_REQUIRED`。文件里的保存值不能代替本次结果。保留显式入口的公式与已支持的普通引用不因此扩大限制。Table 数据体内实际为单格的动态结果不再仅因 Table 被阻挡，实际多格结果与 Table 相交仍会被阻挡；表头与汇总行未得到同样的验证。
- **统计参数限制**：公开的分布、反函数、百分秩和排列函数仍有形状、尾概率、样本规模、精度与收敛限制，按实际诊断判断。`BETA.DIST`／`BETADIST` 的非默认上下界归一化可能因表示误差与形状灵敏度而不可得，即使 Excel 能给值；密度端点写法另有限制。`GAMMA.INV`／`GAMMAINV` 的单位尺度根落入特定次正规范围时也不可得。不要把这些限制说成 Excel 的合法参数边界。
- **复数限制**：`IMTAN`／`IMCOT` 的部分非实轴极点附近因抵消风险报告 `COMPLEX_POLE_CANCELLATION_UNAVAILABLE`；实轴不套用这项保护。`IM*` 的日期样复数分量报告 `COMPLEX_DATE_COMPONENT_UNVERIFIED`，不猜测日期或地区含义。普通非法文本仍按原规则返回错误；不能把保护诊断伪装成 `#NUM!`。
- **债券与证券限制**：迭代 `YIELD`／`ODDFYIELD` 对部分高票息、极端价格与赎回比报告 `BOND_YIELD_PARAMETER_UNAVAILABLE`，单期 `YIELD` 的闭式不套用该限制；合法的长期零息债也可能被限制。部分二月末次付息、早期应计期、二月首期和日期系统转换后的上溢路径另有日期限制；根精度不能确认时报告 `BOND_ROOT_PRECISION_UNAVAILABLE`。按诊断说明具体原因，不把这些输入称为非法。
- **标量辅助与数字成文限制**：`AMORDEGRC` 在 1904 日期系统中，部分接近日期上限的购入日或首期末转换后不可得（`AMORDEGRC_DATE_OVERFLOW_UNVERIFIED`）；请求很大的期号时还可能超过递推预算（`CALCULATION_BUDGET_EXCEEDED`），这不是 Excel 期数上界或耗时保证。`BAHTTEXT`／`NUMBERSTRING` 在极大数的上边界仍可能报告 `NUMBER_WORDS_UPPER_BOUNDARY_PENDING`。

上述不可得会传播到受影响的依赖与读取状态，`IFERROR` 不能把它们变成已验证数值。让 Excel 重算保存件时，Excel 不执行这些保护诊断，可能得到自己的数值、文本或错误。

## 与 Excel 的值仍可能不同的地方

- `LAMBDA` 的可选参数（`[y]` 写法）不受支持，但不报不可得：计算标为完成，结果是 `#VALUE!`，诊断里有 `UNKNOWN_NAME`。Excel 接受这种写法，这个 `#VALUE!` 不是它会给的值。用逗号留空的参数配 `ISOMITTED` 可以计算。
- `BETA.DIST`／`BETADIST` 与 `F.DIST.RT`／`FDIST` 带已知数值差异公开，并非全部与 Excel 逐值相同；保存后让 Excel 重算，结果可能变化。
- 复数函数保留已登记的文本差异，不能承诺文本逐字一致；部分函数兼容 Excel 的数值行为也不代表数学真值保证。
- `AMORLINC`、`ACCRINT`、`ODDFPRICE`、`ODDLPRICE`、`ODDLYIELD`、`YIELD`、`ODDFYIELD` 带已知差异公开，尤其收益率求解可能与 Excel 不同。
- `HOUR`、`MINUTE`、`SECOND` 在恰好 23:59:59.5 这一点：Excel 进到次日，本程序为 23:59:59。
- `TEXT` 的 `A/P` 在极少数格式串或文字值上退回原来的输出。
- `en-US` 下带货币符号的文本没有 Excel 实测。
- 普通加减乘除的结果落进次正规数范围（绝对值小于最小正规数）时，Excel 给 0，本程序保留这个极小值。
- 特定极小结果在 Excel 内存重算时非零，另存的文件缓存却可能为 0；不计算的读取应如实报告文件缓存，不能把它当作本次计算。这是已观测到的有限形态，不推广到所有极小数或所有 Excel／WPS 组合。

结果依赖上面任何一类时，要向用户注明。0.5.0 新增的函数没有做过 WPS 重算的兼容性验证。
